# M4.1 practical-task evidence

**Status:** live Workers AI adapter and deterministic safety integration implemented and independently reviewed on `feat/live-practical-tasks`; live-provider quality evaluation and manual content audit remain.

The learner explicitly submits exactly one currently selected concept ID. This keeps the hackathon task focused and gives the learner direct control over its topic. The Worker resolves the current material and concept revision, loads source chunks server-side, and rejects missing, unselected, cross-owner, stale, or invented references. The same revision and selection gate protects reload and completion, so stale tasks are not rendered or completed. Exact request replay returns the durable result before quota reservation. An atomic owner reservation admits one new request; same-ID pending work replays while a different ID conflicts without another provider or quota call. The UI offers an explicit pending retry with a new ID. The server keeps live pending work, but can replace it once its `created_at` reaches the quota ledger's five-minute stale boundary. The quota reservation then expires the old pending credit. Request-ID gates reject a late result from the replaced provider. A new owned request reserves one `practical` credit immediately before the provider call and settles it only after the result passes deterministic validation and the current-revision, active-space, and account-deletion save gates.

Suitable output includes an allowlisted desk-based modality, objective, ordered instructions, expected output, allowlisted low-risk tools, duration, self-check criteria, structured connectivity disclosure, and structured cost disclosure for standard, simpler, and no-cost variants. The free alternative must declare no cost and every one of its prose and tool fields is rejected if it contains paid, purchase, subscription, fee, licence, or rental terms. Deterministic screening rejects external URLs and physical-action, location, and tool bypasses alongside hazards involving heat or boiling, heights or climbing, medical or ingestion work, biological material, machinery or power tools, vehicles, laboratories, electricity, chemicals, weapons, or specialist supervision in every executable variant. Live results are further restricted to non-networked written analysis using paper, pen, a notes app, or calculator, and reject code/script/shell execution, software installation, credential handling, file operations, and network instructions. An unsuitable decision must contain no executable variants; its fixed bounded rationale is persisted without treating the rejected source hazard as instructions.

Normal local development resolves a Workers AI provider only when a generation POST is made. The provider receives one selected concept label and at most four bounded source ID/text pairs. It does not receive account details, study-space/material/concept revision IDs, source offsets, or completion state. Its strict draft omits trusted identifiers and rationale: the Worker reconstructs the selected concept ID, validates citations against server-loaded context, and supplies fixed suitable/unsuitable rationale. Live configuration fails closed and never falls back to fake content. D1 records provider, model, prompt, and output-schema provenance on each reservation.

Learners can inspect every cited source, and unavailable citations are surfaced instead of silently omitted. They can switch task variants, report completion, and undo it. Completion is stored on the practical task and remains separate from activity attempts, concept progress, and study sessions. If a completion save fails, the visible choice stays on the page with an explicit retry action. Generation is disabled while its request is in flight.

Focused automated coverage uses only synthetic material and fake Workers AI responses; it makes no live or billed calls. It checks durable generation and replay, same-ID and different-ID concurrency, five-minute stale takeover and late-result rejection, all required variants and disclosures, minimized live request shape, source context, completion/undo isolation, broad hazardous-category and URL rejection across variants, executable/external instruction rejection, exact physical-tool and hidden-paid bypasses, quota settlement on rejected output, durable unsuitable output, exactly one selected concept, stale reload/completion rejection, and late material, space-deletion, and account-deletion changes. Keyword and allowlist screening cannot prove semantic safety, so demo content still requires manual audit. Live-provider teaching quality and the PRD content audit remain unverified.
