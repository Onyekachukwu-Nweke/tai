# M4.1 practical-task evidence

**Status:** implemented and independently reviewed on `feat/practical-tasks`; live-provider quality and manual content audit remain.

The learner explicitly submits exactly one currently selected concept ID. This keeps the hackathon task focused and gives the learner direct control over its topic. The Worker resolves the current material and concept revision, loads source chunks server-side, and rejects missing, unselected, cross-owner, stale, or invented references. The same revision and selection gate protects reload and completion, so stale tasks are not rendered or completed. Exact request replay returns the durable result before quota reservation. An atomic owner reservation admits one new request; same-ID pending work replays while a different ID conflicts without another provider or quota call. The UI offers an explicit pending retry with a new ID. The server keeps live pending work, but can replace it once its `created_at` reaches the quota ledger's five-minute stale boundary. The quota reservation then expires the old pending credit. Request-ID gates reject a late result from the replaced provider. A new owned request reserves one `practical` credit immediately before the provider call and settles it only after the result passes deterministic validation and the current-revision, active-space, and account-deletion save gates.

Suitable output includes an allowlisted desk-based modality, objective, ordered instructions, expected output, allowlisted low-risk tools, duration, self-check criteria, structured connectivity disclosure, and structured cost disclosure for standard, simpler, and no-cost variants. The free alternative must declare no cost and every one of its prose and tool fields is rejected if it contains paid, purchase, subscription, fee, licence, or rental terms. Deterministic screening rejects external URLs and physical-action, location, and tool bypasses alongside hazards involving heat or boiling, heights or climbing, medical or ingestion work, biological material, machinery or power tools, vehicles, laboratories, electricity, chemicals, weapons, or specialist supervision in every executable variant. An unsuitable decision must contain no executable variants; its bounded rationale is persisted without treating its explanation of the rejected hazard as instructions.

Learners can inspect every cited source, and unavailable citations are surfaced instead of silently omitted. They can switch task variants, report completion, and undo it. Completion is stored on the practical task and remains separate from activity attempts, concept progress, and study sessions. If a completion save fails, the visible choice stays on the page with an explicit retry action. Generation is disabled while its request is in flight.

Focused automated coverage uses only synthetic material and a fake provider. It checks durable generation and replay, same-ID and different-ID concurrency, five-minute stale takeover and late-result rejection, all required variants and disclosures, source context, completion/undo isolation, broad hazardous-category and URL rejection across variants, exact physical-tool and hidden-paid bypasses, quota settlement on rejected output, durable unsuitable output with a hazard explanation, exactly one selected concept, stale reload/completion rejection, and late material, space-deletion, and account-deletion changes. Keyword and allowlist screening cannot prove that all generated instructions are semantically safe, so demo content still requires manual audit. Live-provider teaching quality and the PRD content audit remain unverified.

The final local gate passed 145 Vitest tests, 48 Playwright tests, all static and documentation checks, the 350-line limit, the production build, and the Wrangler deploy dry run. Fresh migrations through `0017` and a populated `0016 → 0017` upgrade passed with no foreign-key violations.
